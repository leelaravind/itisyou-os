# ADR-0020: TCP — a host-tested state machine on a polled stack

## Status

Accepted and verified for V0.9 (NET09-001).

## Context

V0.8 shipped a datagram-only stack and deferred TCP rather than ship half of
it: a TCP whose retransmission, windowing or teardown is subtly wrong fails
only under loss or reordering, which is exactly when nobody is looking. The
kernel's network stack is polled (the e1000 on QEMU exposes no MSI), syscalls
run with interrupts masked, and kernel stacks are 32 KB with no guard page.

## Decision

1. **All protocol logic lives in `kernel_core::net::tcp`**, a `no_std`,
   `forbid(unsafe_code)` crate module with no kernel dependencies: segment
   codec (pseudo-header checksum, MSS option), the RFC 9293 state machine,
   RFC 5961 reset/SYN handling, one retransmission timer with exponential
   backoff and a retry limit, a receive window equal to free buffer space (so
   the advertised right edge never shrinks). Its methods push outgoing segments
   into a fixed-capacity `Outbox`; they never transmit. That is what makes it
   testable on the host, including two instances talking to each other through
   the codec with sequence numbers wrapping at 2^32.
2. **The kernel side is plumbing**: eight connection slots, a shared outbox,
   RST for segments no connection owns (never to broadcast — that would be a
   reflection amplifier), and time from the TSC because the tick counter is
   frozen inside syscalls. Timers run from every NIC poll; there is no
   background timer, consistent with the rest of the polled stack.
3. **Connections are built in place.** A `Tcb` is 8 KB. Building one by value
   and moving it into the table overflowed the syscall stack in the
   unoptimized build and silently corrupted the capability table next to it.
   Slots are therefore static and reinitialized in place
   (`Tcb::connect_in_place`), never constructed on the stack.
4. **Authority**: `tcp_connect` requires the network capability scoped to the
   destination port; every later call re-checks the handle against that port,
   so narrowing or revoking the handle stops an open connection at its next
   use — the same model as the V0.8 UDP sockets.
5. **Verification against a stack we did not write.** QEMU's user-mode network
   maps 10.0.2.2 to the host loopback, so the guest's peer is the host
   operating system's TCP implementation; the harness's echo endpoint checks
   the byte pattern with its own code. Loss is injected in the guest's transmit
   path (`tcp drop <n>`), so retransmission is exercised against that real
   peer.

## Consequences

- Ring 3 gets client streams only; a passive open exists in the state machine
  but no listen/accept syscalls yet.
- No congestion control beyond an in-flight cap, no RTT estimation, no SACK,
  window scaling or timestamps; ISS is TSC-mixed, not RFC 6528 keyed. All
  stated in `docs/KNOWN_LIMITATIONS.md`.
- A connection's timers advance only while something polls the stack. A
  program waiting on its connection is that something; an orphaned TIME-WAIT
  slot is reclaimed at the next poll.
