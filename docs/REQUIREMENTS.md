# Requirement traceability matrix — ITISYOU OS

States: `IMPLEMENTED+VERIFIED` (with evidence) · `IN PROGRESS` (work ongoing
this session) · `PLANNED` (not started) · `BLOCKED` (reason + required input)
· `NOT APPLICABLE` (reason). Only the first, `BLOCKED` and `NOT APPLICABLE`
are terminal (implementation plan §2); there is no `DONE` or `NOT DONE`
state. `website/scripts/check-consistency.mjs` enforces the vocabulary on
every build, and its `--release` form refuses any non-terminal row before a
version tag is created.

Evidence conventions: `verify.ps1` stage names, `artifacts/qemu/*.result.json`
labels, commit SHAs, CI run links, or file paths.

| AUDIT11-001 | A stored audit trail nobody touched verifies — after any number of boots and records — and checking it mid-boot changes nothing | IMPLEMENTED+VERIFIED | Defect in v0.8.0–v0.10.0, reproduced on the published v0.10.0 BIOS image (SHA-256 `d8416a58…f44f098`): boot 1 `trail_saved records=5`; boot 2 `trail_recovered status=verified records=5`, then `trail_saved records=2`; boot 3, the disk untouched, `trail_recovered status=TAMPERED records=2`. | AUDIT11-002 | Text a program or a disk chose never reaches the console as a line of its own or as a kernel marker | IMPLEMENTED+VERIFIED | Defect in v0.8.0–v0.10.0: ITFS accepted any UTF-8 name, and the kernel echoed names raw — in the audit detail of every `fs_write`/`fs_delete` (`path=…`), in `store ls`, `pkg list` and package recovery — and file contents raw in `store cat`. | SEC11-001 | The audit trail and the package store are the kernel's: no program reaches them through the filesystem syscalls | IMPLEMENTED+VERIFIED | Defect in v0.8.0–v0.10.0: the `fs_*` syscalls addressed every name in the persistent store, so a program holding `fs_write` with no sandbox (the console's default for `run`) could replace `/data/audit.log` — in the limit with a valid empty trail, which verifies — or delete an application's highest `.ok`, a rollback nobody approved.
