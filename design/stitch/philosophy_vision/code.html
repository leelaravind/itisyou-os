Why build another OS?

An operating system is not just a resource allocator; it is the fundamental boundary of trust. We are exploring a research direction focused on structural clarity, minimal trusted computing bases, and deliberate offline capabilities. This is an experiment in radical simplicity.

Core Principles

Our architecture deviates from monolithic norms to explore isolated, explicit, and recoverable states.

memory

Smaller TCB

Minimizing the Trusted Computing Base. Every line of kernel code is a liability. We enforce strict microkernel architectures to push drivers and filesystems to user-space.

In Development

Explicit Authority

Capabilities-based security. Processes must request explicit rights to resources. No implicit access, no ambient authority.

Research

Recoverable Operations

Immutable core states and declarative configurations allow instant rollback. The OS state should be a function of its configuration file.

Research Direction

Linux

Verified
  • 01/ Highly mature, monolithic kernel architecture spanning millions of lines of code.
  • 02/ Production-ready ecosystem supporting vast enterprise and consumer hardware.
  • 03/ Ambient authority model (UID/GID) rooted in decades of POSIX standards.

ITISYOU OS

Experimental
  • 01/ Strictly compartmentalized, experimental microkernel focused on structural proofs.
  • 02/ Highly volatile API, unsupported hardware, built for architectural research.
  • 03/ Explicit capability-based routing requiring intentional privilege escalation.
